# Phase 2 Data Model: User File Management

This design uses the canonical entities in `database-schema.mmd`. File content is stored only in the configured private Supabase Storage bucket; PostgreSQL remains authoritative for identity, ownership, discoverability, quota, hierarchy, and audit metadata.

## Schema Alignment

| Canonical entity | Phase 2 use | Schema impact |
| --- | --- | --- |
| `USER` | Owner and serialization target for quota/folder operations | Apply the already approved nullable `deletedAt` addition |
| `FOLDER` | Permanent, fixed-parent personal hierarchy | Remove legacy runtime `deletedAt`; no other change |
| `FILE` | Active metadata and authoritative retained-byte record | Remove legacy runtime `deletedAt`; no other change |
| `AUDIT_LOG` | Best-effort sanitized records of important successful operations | No change |
| `VERIFICATION_CODE` | Phase 1 identity support | No change |
| `REFRESH_TOKEN` | Phase 1 session support | No change |

No entity, field, key, relationship, constraint, or index beyond the approved diagram is added. Provider or quota workflow state is transient and must not be stored in `AUDIT_LOG`.

## Entity: File

Canonical table: `FILE`

| Field | Type | Rules |
| --- | --- | --- |
| `id` | UUID | Primary key generated by the server before object upload; also supplies the trusted storage-key suffix |
| `ownerId` | UUID | Required `USER.id`; immutable; every read/write scopes by the authenticated owner |
| `folderId` | UUID or null | Optional owned `FOLDER.id`; null means the user's virtual root; mutable only through file move |
| `originalName` | string | Trimmed display metadata, 1–255 Unicode code points, no path separators or C0 controls; never used as an object path |
| `storageKey` | string | Generated internal key `users/{ownerId}/files/{id}`; unique by construction; never returned, audited, or logged |
| `mimeType` | string | Verified canonical value: `application/pdf`, `text/plain`, `image/jpeg`, `image/png`, `image/webp`, or DOCX canonical MIME |
| `size` | bigint | Authoritative bytes, integer from 1 through 5,242,880 inclusive; JSON contracts encode it as a decimal string |
| `extractedContent` | text or null | TXT/PDF extracted text when available; null for images, DOCX, skipped extraction, or failed extraction |
| `createdAt` | UTC timestamp | Original upload time; immutable; drives upload-history buckets |
| `updatedAt` | UTC timestamp | Changes on mutable metadata such as folder move; never substitutes for upload time |

### Derived File properties

- `typeCategory`: `pdf`, `text`, `image`, or `document`, derived from verified `mimeType`.
- `previewKind`: `pdf`, `text`, `image`, or `unavailable`, derived from `mimeType`.
- `extractionState`: `available` only when a supported text-bearing file has non-null extracted content; otherwise `unavailable`. Empty successfully extracted text is stored as the empty string and remains `available`.
- `folderPath`: resolved from same-owner ancestors; root is represented without a database row.
- `stored`: existence of the canonical `FILE` row. Supabase provider state is never treated as a second application-visible lifecycle.

### File validation

- A submitted extension and multipart MIME type are hints only.
- PDF/JPEG/PNG/WebP require byte-signature detection.
- DOCX requires OOXML detection plus `[Content_Types].xml` and `word/document.xml` entries.
- Plain text requires fatal UTF-8 decoding, no NUL, and no C0 controls except tab, LF, and CR.
- Object upload uses the generated key with overwrite disabled.
- An optional destination folder must exist, belong to the same owner, and have a valid same-owner ancestor chain.
- Duplicate `originalName` values are allowed; `id` distinguishes files.

### File state transitions

```text
client-selected
  -> locally-rejected
  -> server-validating
  -> quota-rejected
  -> provider-uploading
  -> metadata-committed (visible/stored)
  -> permanently-deleted (no row; no restore)
```

Validation, quota, provider, or metadata failure never creates an application-visible file. If provider upload succeeds but metadata commit fails, best-effort provider removal runs; a remaining private orphan has no application state and consumes no user quota.

Deletion removes or confirms absence of the provider object before permanently deleting the row. Quota is reclaimed exactly when the row is absent. A known partial failure is retryable and is not represented as a successful state transition.

## Entity: Folder

Canonical table: `FOLDER`

| Field | Type | Rules |
| --- | --- | --- |
| `id` | UUID | Primary key generated by the server |
| `ownerId` | UUID | Required `USER.id`; immutable; all access owner-scoped |
| `parentId` | UUID or null | Optional same-owner `FOLDER.id`; null means virtual root; immutable after creation |
| `name` | string | Trimmed, non-empty display name, maximum 120 Unicode code points; no separators or C0 controls |
| `createdAt` | UTC timestamp | Immutable creation time |
| `updatedAt` | UTC timestamp | Changes on rename |

### Folder invariants

- A virtual root exists per user but is not stored.
- Stored depth is 1–10; creation beneath depth 10 is rejected.
- The ancestor chain must be acyclic and entirely same-owner.
- Sibling names are unique after trimming and Unicode-aware case folding.
- The parent cannot change after creation; Phase 2 does not move folders.
- Permanent deletion requires zero child folders and zero files and never cascades.
- Create, rename, and delete serialize through an owner-scoped lock so sibling and empty-folder checks remain correct under concurrency.

### Folder state transitions

```text
absent -> created -> renamed (zero or more times) -> permanently-deleted
```

There is no deleted state, trash state, restore transition, or retained tombstone.

## Entity: Audit Log

Canonical table: `AUDIT_LOG`

| Field | Type | Phase 2 rule |
| --- | --- | --- |
| `id` | UUID | Generated audit-record identifier |
| `actorId` | UUID or null | Authenticated user for Phase 2 events |
| `action` | string | Allowlisted action such as `file.uploaded`, `file.downloaded`, `file.deleted`, `file.moved`, `folder.created`, `folder.renamed`, or `folder.deleted` |
| `entityType` | string or null | `FILE` or `FOLDER` |
| `entityId` | string or null | Target UUID; safe after permanent deletion |
| `metadata` | JSON or null | Minimal allowlisted values such as verified type category or byte-count string; never content, extracted text, filename paths, storage key, provider URL/error, or credential |
| `createdAt` | UTC timestamp | Audit attempt time |

Audit insertion happens through the shared audit service after the primary successful operation. Failure does not mutate business state and produces sanitized operational logging. Users have no audit read interface in Phase 2.

## Entity: User

Phase 2 consumes canonical `USER.id` and `USER.deletedAt`.

- A deleted user cannot authenticate or own an authorized Phase 2 request.
- The `USER` row is the preferred per-user quota mutex using `SELECT ... FOR UPDATE`.
- No `usedBytes`, quota allocation, reservation, or provider-capacity field is added.

## Transient Model: Upload Item

Client-only queue state, never persisted as a database entity:

| Field | Values / rules |
| --- | --- |
| `clientId` | Locally generated queue identity |
| `file` | Browser `File`, held only for the active interaction |
| `displayOrder` | Stable selection order; requests execute sequentially |
| `folderId` | UUID or null selected at submission |
| `status` | `queued`, `validating`, `uploading`, `processing`, `succeeded`, `rejected`, or `failed` |
| `progressPercent` | 0–100 network progress for this request |
| `result` | Public File view on success |
| `error` | Safe error code/message and optional quota snapshot |

A client batch contains 1–10 items. Earlier successes remain successful when later items fail or exceed quota.

## Transient Model: File Query

| Field | Type / default | Validation |
| --- | --- | --- |
| `search` | string, absent | Trim; empty becomes absent; maximum 200 characters |
| `type` | enum, absent | `pdf`, `text`, `image`, or `document` |
| `folderId` | UUID, `root`, or absent | `root` means `folderId IS NULL`; UUID must identify an owned folder; absent searches all locations |
| `sort` | enum, `uploadedAt` | `name`, `size`, or `uploadedAt` |
| `direction` | enum, `desc` | `asc` or `desc` |
| `page` | positive integer, `1` | Reject malformed/non-positive values |
| `pageSize` | positive integer, configured default `20` | Maximum configured `100`; contract documents safe handling |

Every query includes `ownerId = authenticatedUser.id`. Ordering always appends `FILE.id` in the same direction as a stable tie-breaker. The response includes total items, total pages, current page, and page size.

## Transient Model: Quota Snapshot

| Field | Type | Derivation |
| --- | --- | --- |
| `usedBytes` | decimal string | `SUM(FILE.size)` for authenticated owner, or zero |
| `remainingBytes` | decimal string | `max(104857600 - usedBytes, 0)` |
| `limitBytes` | decimal string | Constant `104857600` |

Admission acquires the user lock, recomputes the sum, and permits the item only when `used + candidate <= limit`. The lock is held through provider upload and metadata commit. Failed uploads release the lock without a new row.

## Transient Model: User File Statistics

| Field | Rules |
| --- | --- |
| `fileCount` | Count of current owned `FILE` rows |
| `storedBytes` | Decimal-string sum of current owned `FILE.size` |
| `quota` | Current Quota Snapshot |
| `typeDistribution` | One entry for every normalized type category represented; each file counted once |
| `uploadHistory` | Exactly 30 entries, one for each local calendar date including today, oldest first, zero-filled |
| `timeZone` | Echoed validated IANA timezone used to define dates |

UTC `createdAt` timestamps are grouped against the supplied IANA timezone. Files before the oldest included local date are excluded. Updates and folder moves never change the upload bucket.

## Relationship Rules

```text
USER 1 -> many FILE
USER 1 -> many FOLDER
USER 0..1 -> many AUDIT_LOG
FOLDER 0..1 -> many FILE
FOLDER 0..1 -> many child FOLDER
```

All relationship traversal in Phase 2 is additionally constrained by authenticated ownership. Foreign and absent identifiers share a safe not-found outcome.
